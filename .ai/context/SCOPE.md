# SCOPE

Last Updated: 2026-05-29

## Project
- 名称: `skoda-music`
- 概述: Android 车机音乐播放器（API17 基线，Kotlin 壳 + C++ 核心）

## Scope Summary
- 当前阶段: S4 子阶段（应用内 EQ 固定 10 段直写试验）
- 阶段目标:
  - 实机已确认系统 EQ 继承不可用，本轮主线回到应用内 EQ。
  - EQ 子页按系统内置 EQ 截图的视觉重做：横屏全屏、一排很窄的 10 段竖滑杆、右侧常见中文预设按钮。
  - UI 和预设不再读取/展示 ROM 内置 bands/presets；页面固定为常见 10 段与常见预设。
  - 底层先采用“10 段逻辑 band -> Android Equalizer band 0..9 直接写入”的试验方案，供 API17 实机验证。
  - 所有音效写入必须 fail-open：失败不闪退、不影响播放、不写入失败配置。

## In Scope
- EQ 页面视觉重做:
  - 固定横屏全屏子页。
  - 左侧固定 10 段频点竖滑杆：`31Hz / 62Hz / 125Hz / 250Hz / 500Hz / 1kHz / 2kHz / 4kHz / 8kHz / 16kHz`。
  - 滑杆轨道改窄，接近系统 EQ 截图观感，不再使用当前粗滑块/粗轨道。
  - 右侧固定常见中文预设按钮：`默认 / 流行 / 摇滚 / 爵士 / 古典 / 舞曲 / 人声 / 低音增强 / 高音增强 / 自定义`。
  - 切换预设后 10 个滑杆位置立即同步到对应预设曲线。
  - 用户拖动任意滑杆后进入“自定义”。
- EQ 数据与应用策略:
  - UI 不读取、不展示 ROM 返回的 preset 名称或 band 数量。
  - 底层本轮不做最近频点映射、不做插值映射，先强制尝试写入 Android Equalizer band index `0..9`。
  - 10 段必须分开处理：每个 band 独立 try/catch、独立记录结果、独立提示，不允许“一段失败就直接判定全部不可用”。
  - 不允许预先禁用 band，也不允许因为历史失败永久禁用 band；只有用户实际改动某个 band、或预设应用实际写到该 band 时，底层真实抛错后才提示。
  - 可写入的 band 继续生效；真实写入失败的 band 只跳过本次该段写入。
  - 失败提示需要基于真实异常触发，并尽量具体到频段或汇总失败频段，例如“8k/16k 本次写入失败，已跳过”。
  - 配置保存必须改为“先应用，成功部分确认后再保存”；真实写入失败的 band 不得写入持久化配置，避免下次启动反复失败或无法启动。
  - EQ 初始化、预设应用、自定义滑杆写入都必须 fail-open，不影响播放主链路。
- 联动保持:
  - 设置页 EQ 开关保留，并继续与 EQ 子页同步。
  - 子页选择预设或拖动滑杆时仍可自动开启应用内 EQ，并同步外部开关。

## Out of Scope
- 本阶段不做:
  - 系统 EQ 继承继续推进（已由实机结论判定不可用，当前不作为主线）。
  - 最近频点映射或曲线插值映射。
  - 读取/展示 ROM 内置 bands/presets。
  - `BassBoost/Virtualizer/Reverb/LoudnessEnhancer` 等附加音效。
  - 多套自定义曲线保存、导入导出、复杂音效中心。
  - 播放主链路重构（仍保持 Emby-only、IPv4-only、download-only）。

## Success Criteria
- 视觉验收:
  - EQ 子页固定显示 10 段窄竖滑杆，整体接近用户提供的系统 EQ 截图。
  - 不再出现 ROM preset 名、`Preset #N`、设备 band 数、空 bands/presets 提示。
  - 预设按钮固定中文，选中态清晰。
- 交互验收:
  - 切换预设后 10 个滑杆位置立即变化。
  - 拖动任意滑杆后进入“自定义”。
  - 设置页开关与子页操作保持同步。
- 稳定性验收:
  - 任何 band 写入失败都不闪退、不停播。
  - band 写入按段处理：真实写入成功的段生效，真实写入失败的段跳过本次写入并提示。
  - 不做预判禁用，不因历史失败永久禁用 band；每次改动都以底层真实写入结果为准。
  - 真实写入失败的 band 不保存到持久化配置，下次启动不会因失败配置循环触发问题。
  - 本地构建通过，API17 guardrails 通过。
- 实机验收:
  - 在目标 API17 车机验证 10 段直写哪些 band 可用、哪些 band 失败，并能从 UI/toast/log 明确观察。

## Design Direction
- 采用固定 10 段应用内 EQ 试验方案:
  - UI 固定，不再由 ROM 能力驱动。
  - 底层强制尝试 `band 0..9` 直接写入。
  - 每个 band 独立 fail-open，不能整体熔断，也不能预先禁用 band。
  - 配置持久化从“先保存再应用”改为“先尝试应用，再保存成功/有效配置”。
- 该方案是为了实机验证厂商系统 EQ 显示 10 段时，第三方 `Equalizer` API 是否也能写入 10 段。

## Constraints
- 平台红线: `minSdk=17` 不可变，目标设备为 Android 4.2.2 车机。
- 稳定性优先: 任何音效能力失败都不得阻塞播放，不得导致启动失败。
- 配置安全: 失败配置不得落盘；落盘配置必须能在下一次启动安全恢复。
- ROM 差异: 系统内置 EQ 的 10 段能力不等于 Android 公共 `Equalizer` API 必然暴露 10 段，本轮以实机验证为准。

## Open Questions
- 目标车机上 Android `Equalizer` API 是否允许写入 band `5..9`。
- 如果部分 band 真实写入失败，最终产品版是否继续保留 10 段直写，还是回到最近频点/插值映射。
- 真实失败提示采用逐段 toast 还是单次汇总 toast，规划阶段需定稿。
