# SCOPE

Last Updated: 2026-06-01

## Project
- 名称: `skoda-music`
- 概述: Android 车机音乐播放器（API17 基线，Kotlin 壳 + C++ 核心）

## Scope Summary
- 当前阶段: S4 子阶段（应用内保真音效引擎需求收敛）
- 阶段背景:
  - 系统 EQ 继承已由实机反馈判定不可用。
  - Android `audiofx.Equalizer` 固定 10 段直写在目标车机上仍不可靠，不能作为主线继续投入。
  - 用户目标不是“重低音/突出人声/更猛的 EQ”，而是尽量还原原声，让乐器、鼓声、人声更自然、更清楚、更有层次。
- 阶段目标:
  - 从“系统/ROM EQ 能力接入”转向“App 播放链路内自研保真音效”。
  - 在不破坏 API17 兼容和播放稳定性的前提下，于 ExoPlayer PCM 输出前做轻量 DSP 处理。
  - 第一版以自然听感、低失真、可旁路为目标，而不是追求夸张音效。

## In Scope
- 音效目标与产品形态:
  - 设置页保留音效开关，含进入音效子页入口。
  - 音效子页从“10 段 EQ 优先”调整为“音质模式优先”。
  - 第一版模式固定为：`原声 / 保真 / 清晰 / 动感 / 柔和`。
  - `原声` 表示完全旁路 DSP，仅保留播放主链路。
  - `保真` 作为默认推荐模式，轻微修正车机喇叭/功放带来的闷、糊、暗，不强行染色。
  - `清晰` 轻微提升人声和乐器存在感，但避免刺耳。
  - `动感` 轻微增强鼓点和节奏弹性，但控制低频轰头。
  - `柔和` 降低刺耳高频，适合车机大音量长时间播放。
- 自研音效链路:
  - 基于当前 ExoPlayer 2.17.1 播放链路，优先通过自定义 `AudioProcessor` 接入 PCM 处理。
  - 不再依赖 Android `audiofx.Equalizer` 作为主后端。
  - 不再依赖系统 EQ open/close 或 ROM 内置音效能力。
  - 第一版 DSP 处理保持克制：前级增益/自动降增益、少量 biquad 滤波器、轻量防削波策略。
  - 所有 DSP 参数按模式内置，不要求用户理解 10 段频点。
- API17 兼容与稳定性:
  - `minSdk=17` 不可变，不能引入要求更高 API 的音频库或 Android 新 API。
  - 处理链路必须 fail-open：DSP 初始化失败、格式不支持、运行异常时自动旁路原声播放。
  - 任何音效问题不得导致闪退、停播、启动失败或配置写入后循环崩溃。
  - 配置持久化必须安全：仅保存模式/强度等稳定配置，不保存会导致下次启动崩溃的临时失败状态。
- 验证与观测:
  - 增加日志区分：DSP 启用、DSP 旁路、格式不支持、处理异常、模式切换。
  - API17 实机验证重点从“band 是否写入成功”改为“是否可听出自然变化、是否稳定不卡顿、是否无爆音破音”。

## Out of Scope
- 本阶段不做:
  - 继续推进系统 EQ 继承。
  - 继续把 Android `audiofx.Equalizer` 固定 10 段直写作为主方案。
  - 影响系统其他 App 或系统全局声音。
  - 重写播放器为纯自研解码 + `AudioTrack` 输出。
  - 复杂音效中心：混响、环绕、空间音频、动态压缩器、多段可视化分析等。
  - 多套用户自定义曲线保存、导入导出。
  - 第一版强度滑杆。
  - 把 10 段高级 EQ 作为第一入口；如保留，最多作为后续高级设置。
  - 变更现有 Emby-only、IPv4-only、download-only 播放主策略。

## Success Criteria
- 听感验收:
  - `原声` 模式应与当前无音效播放接近。
  - `保真` 模式应比原声更清楚、更不糊，但不明显偏重低音或突出人声。
  - `清晰 / 动感 / 柔和` 能听出方向差异，但不出现明显失真、刺耳、轰头。
- 交互验收:
  - 设置页音效开关与子页模式选择状态同步。
  - 切换模式后当前播放尽量实时生效；如需重新创建播放器，必须有明确策略且不能破坏播放体验。
  - 默认推荐模式为 `保真`。
- 稳定性验收:
  - DSP 不支持当前音频格式时自动旁路原声，并记录日志/必要提示。
  - DSP 处理异常自动旁路原声，不闪退、不停播。
  - API17 构建通过，API17 guardrails 通过。
  - 目标车机长时间播放无明显卡顿、爆音、破音。
- 工程验收:
  - 旧 `audiofx` 相关实现可先保留，但默认主线切到自研 DSP 后端。
  - 音效后端应与 UI 状态分离，后续可替换/扩展算法。

## Design Direction
- 推荐方案: Option B（Balanced）
  - 使用 ExoPlayer 2.17.1 自定义 `AudioProcessor` 在 PCM 输出前处理音频。
  - 第一版做“模式化保真音效”，而不是 10 段 EQ 专家界面。
  - 内部算法优先采用少量稳定滤波器和防削波策略，避免 CPU 压力和兼容风险。
  - UI 面向听感：`原声 / 保真 / 清晰 / 动感 / 柔和`，后续再考虑高级 EQ。
- 技术原则:
  - 处理越少越好，默认不夸张调音。
  - 任何不确定能力都必须旁路原声。
  - 不依赖 ROM 厂商私有音效能力。
  - 不牺牲播放稳定性换音效。

## Constraints
- 平台红线: `minSdk=17` 不可变，目标设备为 Android 4.2.2 车机。
- 依赖约束: 不引入要求 `minSdk > 17` 的音频处理依赖；优先纯 Kotlin/Java 实现轻量 DSP。
- 播放链路约束: 继续使用当前 ExoPlayer 2.17.1 播放抽象，不重写整体播放器。
- 稳定性优先: 音效是增强能力，不是播放必要条件；失败必须 fail-open。
- 性能约束: API17 车机 CPU 能力有限，第一版算法必须轻量，避免高阶复杂处理和频繁分配。
- 音质约束: 目标是自然、还原、层次，不是重低音优先或人声突出优先。

## Open Questions
- 模式切换是否可通过共享 DSP 配置实时生效；若 ExoPlayer 音频处理链需要重建，执行阶段需优先避免短暂重载。
- 实机调音后是否需要第二阶段加入高级 EQ 或强度滑杆，当前不进入第一版 scope。
