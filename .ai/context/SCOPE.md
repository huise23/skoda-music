# SCOPE

Last Updated: 2026-05-19

## Project
- 名称: `skoda-music`
- 概述: Android 车机音乐播放器（API17 基线，Kotlin 壳 + C++ 核心）

## Scope Summary
- 当前阶段: S4 子阶段（歌词居中稳定性改造 + 均衡器能力规划）
- 阶段目标:
  - 将首页歌词显示从“单 TextView 高亮滚动”收敛为“当前行独立中线容器 + 上下文分区”方案，提升当前行视觉稳定性。
  - 产出均衡器/音效优化的可执行技术规划（方案、兼容性、风险、验收口径），不在本阶段直接上线完整音效功能。

## In Scope
- 歌词布局改造范围（UI/交互层）:
  - 评估并落地“上文容器 + 当前行居中容器 + 下文容器”的三段结构（目标页面：Home 歌词面板）。
  - 明确“无上一句/无下一句/无歌词/歌词加载中/超长歌词行”下的显示与对齐行为。
  - 保持现有歌词获取与解析链路不变（LrcApi 请求、缓存、时间轴解析逻辑不重写）。
  - 给出“是否可长期稳定居中”的边界结论与验证清单（避免仅凭主观判断）。
- 均衡器规划范围（仅规划，不做大规模实现）:
  - 梳理 API17 可用技术路径：`android.media.audiofx.Equalizer` 及相关音效组件可行性。
  - 明确与当前 Exo 播放引擎的接线点（音频 session 生命周期、创建/释放时机）。
  - 规划最小 MVP：开关、预设、增益范围、失败降级（fail-open，不影响主播放）。
  - 输出后续执行所需的任务拆分输入（供 `ai-planning` 使用）。

## Out of Scope
- 本阶段不做:
  - 全量音效系统上线（完整 UI、复杂预设管理、导入导出、自定义曲线编辑器）。
  - 跨协议/跨后端改造（仍保持 Emby-only）。
  - 播放主链路重构（不替换当前 Exo 引擎、不改 download-only 主策略）。
  - 与本阶段无关的 S4 外部验收任务（车机窗口、PostHog 在线查询、更新安装实机闭环）。

## Success Criteria
- 歌词方向:
  - 形成明确布局方案并完成可执行验收条目。
  - 对“当前行居中”给出客观结论：在哪些条件下保证居中，哪些边界场景只能“近似居中”。
  - 不引入播放阻塞或歌词串歌回归。
- 均衡器方向:
  - 输出一份可进入实施阶段的技术规划结论（含 API17 兼容性、接线点、风险、降级策略、MVP 范围）。
  - 规划结果可直接转为任务（Ready），而不是停留在概念描述。

## Constraints
- 平台红线: `minSdk=17` 不可变，目标设备为 Android 4.2.2 车机。
- 稳定性优先: 任何音效能力都不得阻塞主播放链路；失败必须 fail-open。
- 现有基线约束: 保持 Emby-only、IPv4-only、download-only 主链路。
- 车机场景约束: UI 必须适配 1024x600 横屏，触控命中与可读性优先。

## Open Questions
- 歌词“永远在最中间”口径是否接受边界例外：
  - 首句/末句、行高突变、超长自动换行、多语混排时是否定义为“视觉中心优先”而非数学绝对中心。
- 三段容器是否保持当前“单 TextView 富文本高亮”实现，还是切分为三个 TextView/Recycler 结构。
- 均衡器首版交互深度：仅预设切换，还是包含自定义 band 增益调节。
- 均衡器设置是否全局持久化，还是按会话临时生效。
- 是否需要同步规划 `BassBoost/Virtualizer`，还是先限定 Equalizer 最小闭环。
