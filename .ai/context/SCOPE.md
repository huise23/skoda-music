# SCOPE

Last Updated: 2026-05-27

## Project
- 名称: `skoda-music`
- 概述: Android 车机音乐播放器（API17 基线，Kotlin 壳 + C++ 核心）

## Scope Summary
- 当前阶段: S4 子阶段（系统 EQ 继承接线）
- 阶段目标:
  - 优先让播放链路接入系统自带音效（系统 EQ）而不是应用内 EQ。
  - 保持现有设置页结构不变，先不改入口和页面布局。
  - 启动时默认关闭应用内 EQ，先尝试系统 EQ；系统不可用时给出提示，并允许手动开启应用内 EQ。

## In Scope
- 系统 EQ 继承能力接线（Option B）:
  - 在播放 session 生命周期中补齐系统音效会话接线（open/close）。
  - 在设置页保持现有结构不改动，现阶段不调整 EQ 页面入口布局。
  - 启动时默认停用应用内 EQ 配置，优先尝试系统 EQ 链路。
  - 当系统 EQ 接管不可用或失败时，提供 toast 提示。
  - 保留“可手动开启应用内 EQ”作为兜底能力。
- 保留现有应用内 EQ 代码:
  - `EqualizerManager` 与 EQ 子页代码先不删除，便于回退和对照调试。

## Out of Scope
- 本阶段不做:
  - 全量音效中心重构（导入导出、自定义曲线编辑器、复杂预设管理）。
  - `BassBoost/Virtualizer` 等附加音效扩展。
  - 设置页信息架构重做（入口、分组、视觉层级保持现状）。
  - 跨协议/跨后端改造（仍保持 Emby-only）。
  - 与系统 EQ 接线无关的外部窗口任务。

## Success Criteria
- 播放链路:
  - 播放启动后优先走系统 EQ 接线尝试，不自动启用应用内 EQ。
  - 系统 EQ 不可用时不影响播放（fail-open），并有明确 toast 提示。
- 交互链路:
  - 设置页现有结构不变化。
  - 用户仍可手动开启应用内 EQ（作为系统 EQ 不可用时的兜底）。
- 验证链路:
  - 本地构建通过。
  - API17 实机可观察到“系统 EQ 尝试 + 不可用提示 + 手动应用 EQ 兜底”闭环行为。

## Design Direction
- 采用 Option B（平衡方案）:
  - 先做系统 EQ 接线；
  - 保留应用 EQ 但默认不自动介入；
  - 系统不可用则提示，允许用户手动切回应用 EQ。
- 设置页先不动，避免同轮引入 UI 范围扩张。

## Constraints
- 平台红线: `minSdk=17` 不可变，目标设备为 Android 4.2.2 车机。
- 稳定性优先: 任何音效能力都不得阻塞主播放链路；失败必须 fail-open。
- 现有基线约束: 保持 Emby-only、IPv4-only、download-only 主链路。
- ROM 差异约束: 车机 ROM 对系统音效支持不一致，必须允许“系统失败 -> 手动应用 EQ 兜底”。

## Open Questions
- 系统 EQ 接线在目标 ROM 上是否可稳定触发（需实机验证）。
- 系统 EQ 不可用时的 toast 文案是否需要区分“不支持”与“暂时失败”。
